# SONGYU v0.3.2｜自动调教、音乐表现力与完整制作流水线

**Owner：红茶（音乐引擎 / Agent）＋ 小由（交互 / UX）**

仓库：https://github.com/cicikat/SONGYU_music

目标：从当前能够生成真实中文歌声，提升到**自动生成具有乐句表现力、可试听、可编辑、可导出成品的短歌**。

本轮重点不是增加模型，而是让现有 LLM、MelodyDraft、OpenUtau、绮萱和 FluidSynth 真正协同工作。

## P1｜红茶：自动歌声调教

### 1.1 增加 Automatic Performance Planning

当前已经具备：

- Pitch Bend
- Vibrato
- DYN
- Consonant Offset
- natural / soft / strong

但目前的调教主要是固定参数映射。

新增基于实际歌曲内容的自动调教层：

`SongPlan + MelodyDraft + 歌词 + 音符 → PerformancePlan → USTX → 绮萱 WAV`

调教层自动分析：

- 乐句起点与结尾
- 音符间的音程
- 是否连续发声或存在休止
- 长音与短音
- 重复音
- 旋律高潮
- 当前乐句的情绪与强度
- 歌词标点与自然停顿

生成每句、必要时每音符的演唱表现数据。

### 1.2 自动音高处理

不能继续只使用固定直线音高或同一套颤音。

需要根据旋律自动生成：

- 连音时柔和的音高过渡。
- 跳进时有控制的起音。
- 重复音之间自然衔接。
- 长音稳定后适量进入 Vibrato。
- 句尾的自然收束。
- 相邻音符之间避免不合理的滑音。

调教曲线必须严格匹配 OpenUtau 的实际坐标、音高单位和时间单位。

不要通过随机抖动 MIDI 音高冒充自然演唱。

### 1.3 自动力度与发音

根据乐句生成 DYN 曲线，允许表现句首、高潮、句尾的动态变化。

根据歌词与音符时长处理辅音起音和发音偏移。

不允许无条件将所有音节提前相同毫秒数。

对于模型不支持的呼吸、气声或其他参数，不要通过伪造 USTX 属性假装已经实现。

必要时可以通过乐谱休止、力度曲线和明确支持的表达参数完成自然处理。

### 1.4 自动调教与人工修改共存

实现两个模式：

**Auto**：由系统根据音乐内容自动规划表达。

**Manual Override**：用户明确修改的参数优先于自动结果。

支持：

- 一键自动调教全曲。
- 仅自动调教某一句。
- 保留旋律、重新调教演唱。
- 恢复上一版调教。
- 锁定用户手动修改的表达数据。

调教数据需要随 SongProject 保存。

仅修改表达数据时，不得重新调用 LLM 生成歌词或音符。

## P2｜红茶：自动混音和空间效果

### 2.1 修复音频总线结构

目前 `src/audio.ts` 将音轨汇集到一个 master，缺少清晰的分轨处理。

调整为：

```text
绮萱原始干声 WAV
    ↓
人声增益 / EQ / 压缩
    ├── Dry Vocal Bus
    └── Reverb Send
             ↓
         Vocal Bus
             ↓
伴奏各轨 → 增益 / 声像 / 必要 EQ
             ↓
         Master Mix
             ↓
     限峰 / WAV / MP4
```

必须保留原始干声。

混响和空间效果作用在混音阶段，不要破坏绮萱原始 WAV。

### 2.2 自动人声处理

实现克制的基础处理：

- 清理不必要的低频。
- 控制人声动态。
- 必要的齿音控制。
- 轻微、可配置的房间混响。
- 与伴奏匹配的响度。

处理参数根据实际音量与频谱调整。

不能把固定 EQ、压缩和混响参数写死成所有歌曲的唯一效果。

加入自动分析，但保留可调整默认值。

避免过度压缩、过量混响以及明显的泵吸感。

### 2.3 自动伴奏混音

分析各轨：

- 鼓
- 贝斯
- 吉他
- 钢琴 / 和弦
- 器乐旋律
- 绮萱人声

提供初步自动音量平衡与声像布局。

重点避免所有轨道堆在中央。

注意不要让伴奏掩盖中文人声，也不要简单通过降低所有伴奏音量来解决冲突。

### 2.4 统一导出

浏览器试听、WAV 导出和 MP4 必须使用同一版处理后的混音结果。

至少能导出：

- 人声原始干声
- 人声处理后版本
- 伴奏
- 最终混音

同一项目再次导出，不应因为处理顺序改变而得到无法解释的不同结果。

## P3｜红茶：加强真正的一键自动化

在 v0.3.1 `/api/compose` 基础上完善以下完整流程：

```text
用户输入自由主题 / 中文歌词
             ↓
         真实 LLM
             ↓
       SongPlan
             ↓
       MelodyDraft
             ↓
    旋律与和声协调验证
             ↓
      FluidSynth 伴奏
             ↓
     自动 PerformancePlan
             ↓
  OpenUtau Bridge / 绮萱推理
             ↓
       歌声质量检查
             ↓
        自动混音
             ↓
        用户试听
             ↓
       WAV / MP4 导出
```

用户不需要手动操作 OpenUtau GUI。

正式链路必须通过现有无窗口 Bridge 调用实际引擎。

自动化要求：

1. 自动检查 LLM、声库、声码器、FluidSynth、FFmpeg 是否就绪。
2. 自动执行用户选择的创作任务。
3. 生成失败时记录具体阶段，不把失败状态伪装成成功。
4. 允许对失败的单句重试，而不是整首歌曲重跑。
5. 已通过的生成阶段复用有效缓存。
6. 用户修改第二句时，第一句保持有效。
7. 不重复下载声库、重新安装依赖或反复启动 GUI。
8. 缓存失效必须考虑音符、歌词、调教和渲染版本。
9. 生成过程可以查看真实状态；不使用虚假的百分比。
10. 不能静默把真实模型生成换成预设旋律、固定歌词或 Mock。

优先复用现有服务和任务机制，不重新引入一套大型调度架构。

## P4｜小由：自动化交互接入

小由的 Agent 负责以下前端能力，红茶不代改 UI。

**自由创作页面**

- 输入主题或自己的歌词。
- 点击一次即可发起完整创作。
- 显示实际生成状态。
- 完成后直接试听。

**歌姬调教页面**

- 自动调教开关。
- 单句自动调教按钮。
- natural / soft / strong 等表现选择。
- 适度的手动参数控制。
- 原始干声与处理后效果对比。

**混音页面**

- 人声、伴奏音量。
- 混响强度。
- 预设混音与自定义混音切换。
- 单句重新演唱后正确更新播放结果。

新界面必须连接真实 SongProject 和共享 API。

Mock 仅用于小由独立开发，不能作为最终真实生成的证明。

所有共享 Schema 改动先由两人确认。

## P5｜完成开发后统一真实验收

使用用户当前已配置的 LLM API 和本机已安装的绮萱。

本轮正式验收不能直接加载之前的 A/B/C 测试工程。

### 5.1 三组全新输入

选择此前没有用于项目测试的原创内容。

分别测试：

- 仅给创作主题。
- 用户自己填写中文歌词。
- 在生成歌曲后修改一句歌词、锁定音符并改变演唱表现。

记录每次真实模型来源、请求 ID、音符及音频生成结果。

### 5.2 人声 A/B 对照

对同一段实际旋律生成：

A. 无新增自动调教的原版绮萱干声。

B. 自动调教后的绮萱干声。

C. 自动调教加混音处理版本。

同一旋律、同一歌词、同一声库比较，不能把不同旋律造成的变化冒充调教效果。

自动分析：

- 实际音高与目标音符的偏差。
- 长音的稳定性。
- 起音与休止位置。
- 音频静音、削波、异常峰值。
- 歌声是否存在明显提前、拖尾或被截断。
- RMS、峰值及可测的响度指标。

另进行人耳试听，记录旋律感、连贯性、咬字、句尾、混响和空间感。

客观指标通过不等于音质优秀。

### 5.3 全曲真实导出

通过正式网页完成至少一首全新短歌。

生成：

```text

├── input.json
├── song-plan.json
├── melody-draft.json
├── performance-plan.json
├── project.json
├── vocal-dry.wav

├── vocal-processed.wav
├── instrumental.wav
├── final-mix.wav
├── final-pv.mp4
└── acceptance-report.md
```

如某项失败，不生成占位文件。

不得提交模型权重、个人密钥及大体积音频到 Git。

代码完成后执行：

## 最终验收标准

用户输入一段新的原创歌词，SONGYU 完成真实作曲、绮萱演唱、自动调教和混音，无须操作 OpenUtau 编辑器。

用户能试听干声、调教后人声以及完整混音，也能单独重唱一句。

最终 WAV 与 MP4 均使用当前工程的真实生成结果。

**不再以“成功生成 WAV”作为音质达标；必须同时证明动态创作、演唱表现、混音和可编辑性。**
