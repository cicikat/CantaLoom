# SONGYU v0.3.1｜自由音乐创作完整闭环

项目：`D:\ai\hacson\music_agent`

仓库：https://github.com/cicikat/SONGYU_music

Owner：红茶（Backend / AI / Music Engine）、小由（Frontend / UX）

## 核心目标

用户从 SONGYU 网页输入一段**此前从未使用过的原创中文歌词或创作意图**，系统实际完成：

创作意图 → LLM 规划 → 动态歌词 → 动态旋律 → 伴奏编曲 → 绮萱演唱 → 局部编辑与重唱 → 混音试听 → WAV / MP4 导出。

所有数据来自本次用户输入与真实生成结果。

正式创作模式不得以旧歌词模板、固定音阶、三种预设曲风、预录音频、测试夹具或缓存好的验收作品代替生成。

保留旧工程兼容和 Mock 开发环境，但新自由创作路径不得静默调用它们。

## 二、红茶｜自由创作后端

### B1. 取消新创作流程对旧预设的依赖

重点检查：

- `src/melody.ts`
- `src/composer.ts`
- `src/guided-composer.ts`
- `src/composition.ts`
- `src/model.ts`
- `shared/song-plan.mjs`
- `server/services/planner.mjs`
- `server/services/melody.mjs`

当前 `createFreeProject()` 仍使用旧版 `createProject()` 和固定曲风。

改为真正的自由工程初始化与创作规划。

新模式至少允许：

- 自由描述歌曲主题、情绪与画面。
- 手写任意 1–8 句原创中文歌词。
- 不指定曲风时由 LLM 规划。
- 自己指定 BPM，或由规划器合理选择。
- 根据歌词长度、乐句及目标时长安排时间轴。
- 支持重复段、留白、延音和不同乐句长度。

短歌目标维持约 20–30 秒。

旧版三种曲风可以保留在历史工程和兼容模式中，但新流程不能依赖它们生成创作结果。

确保旧工程能继续导入，必要时增加明确版本或模式字段及迁移校验。

### B2. 把 SongPlan 与 MelodyDraft 接成真正的单次创作

目前宏观规划与具体旋律生成是两条独立能力。

建立统一的创作用例：

1. 接收本次用户输入。
2. 调用真实 LLM 生成或确认 SongPlan。
3. 用户手写歌词时原样保留。
4. 未提供歌词时由 LLM 原创作词。
5. 根据实际 SongPlan 生成 MelodyDraft。
6. 校验歌词、音高、节奏与和声兼容。
7. 根据最终旋律和和声生成伴奏。
8. 将全部结果应用到同一个 SongProject。

注意顺序：不能后续重新应用旧 SongPlan 时把已经生成的 MelodyDraft 覆盖回旧音阶模式。

支持失败保护：任意一步失败，不能把半成品当成已经完成的正式工程。

必要时新增一个创作编排服务，但不引入多 Agent 框架。

### B3. 动态伴奏与人声必须协调

新旋律不仅要与音阶兼容，还要与伴奏共同组织。

检查：

- 主旋律是否存在连续机械音阶。
- 歌声与器乐 melody 轨是否冲突。
- 贝斯是否跟随正确和弦根音。
- 吉他、钢琴是否在合适时刻进入。
- 主歌、副歌是否具有实际不同的力度与密度。
- 休止符是否给歌词留出空间。
- 是否存在音域过高、过低或频繁跳进的问题。

改进乐句动机、旋律重复变化、节奏型和伴奏配器。

不能靠随机改变几个音符假装产生不同作品。

新创作模式应能针对不同用户输入生成不同的有效音乐结构，而不是给固定模板改标题。

### B4. 绮萱演唱表现

复用已有 Performance 参数：

- natural
- soft
- strong
- transitionMs
- vibratoDepth
- dynamics
- consonantMs

检查实际 USTX 输出和真实歌声音频。

重点改善：

- 音符之间的过渡。
- 句末长音。
- 中文辅音起音位置。
- 句内换气与停顿。
- 强弱起伏。
- 过度颤音和突然滑音。

不要以参数越多、PCM 差异越大作为音质更好的证明。

每次调教必须允许保留旋律，只重新生成对应歌声。

### B5. 单句修改与锁定

验证以下四种操作：

1. 保留歌词，重生成本句旋律。
2. 保留旋律，只改变本句演唱表现。
3. 锁定部分音符，让 LLM 补全剩余音符。
4. 改写第二句，不影响第一句音符、歌词、伴奏锁定内容与有效人声缓存。

失败或超时不得覆盖工程。

## 三、小由｜自由创作前端

本部分由小由的 Agent 执行，红茶的 Codex 不直接修改小由负责的 UI 文件。

### F1. 自由创作入口

新增明确的自由创作入口，支持两种模式：

**主题创作**：用户输入一句创作想法，AI 生成歌曲。

**歌词创作**：用户粘贴自己的多行歌词，AI 为歌词作曲。

不要求先选择三种固定曲风。

展示真实生成阶段，而不是只有一个笼统的加载状态。

### F2. 钢琴卷帘

接入现有 MelodyDraft。

实现：

- 展示歌词对应音符。
- 编辑音高、起始时间与长度。
- 单音符锁定。
- 乐句锁定。
- 单句重生成。
- 试听编辑前后的结果。

保存必须写回现有 SongProject，不建立另一套 UI 专用乐谱。

### F3. 歌姬调教面板

接入已有 Performance Schema。

允许选择自然、轻柔、强烈，并在需要时调整具体参数。

必须支持：

- 调教前试听。
- 修改参数。
- 仅重新演唱当前句。
- 对比原版和新版。
- 查看真实引擎生成状态。

不能只有看似可操作、但未进入推理链路的滑块。

### F4. Mock 与真实 API

为 `/api/melody` 补齐 Mock。

Mock 负责帮助前端独立开发交互；真实模式必须调用实际 LLM 和绮萱。

界面清楚区分 Mock、真实 LLM、真实歌声与缓存命中。

前端调用现有 `src/api/client.ts`，不要自己重新建立另一套 HTTP 请求逻辑。

## 五、修改全部完成后，再做集中验收

本次最终验收必须运行真实模式。

先完成全部代码修改、共享契约对齐和前端接线；再运行构建与自动测试。最后执行实际 LLM + 绮萱 + 导出端到端测试。

### T1. 自动回归

执行：

```powershell
npm run build
npm test
npm run test:e2e:mock
npm run test:e2e
.\start.bat --check
```

根据新功能增加必要测试。

### T2. 真实动态创作

测试时通过正式网页创建一个全新工程。

测试人员现场输入原创内容，不能从已有测试样本中直接读取生成结果。

至少三组：

**案例 A：自由主题**

只输入一段新主题，让 LLM 创作歌词、旋律和编曲。

**案例 B：用户自写歌词**

输入全新多行歌词，验证完整保留字词，并产生真实旋律。

**案例 C：局部修改**

基于 B，锁定一部分音符，只重生成指定乐句，随后只修改演唱表现。

每组都需要：

- 真实 LLM 请求与模型来源记录。
- 本次生成的 SongPlan 和 MelodyDraft。
- 非均匀音符时值与实际休止。
- 真实 MIDI。
- FluidSynth 真实伴奏。
- 绮萱真实中文演唱。
- 浏览器全曲试听。
- 最终 WAV。
- 最终 MP4。
- 中文字幕及音频同步验收。

禁止用直接调用后端脚本的成功替代正式网页完整流程。

### T3. 排除硬编码与缓存假阳性

验证：

1. 清除本次测试工程状态后仍能从零创作。
2. 两段不同输入产生不同歌词与旋律数据。
3. 新生成结果能够追溯本次 LLM 请求。
4. 真实模式不调用 Mock 响应。
5. 不读取之前 A/B/C 测试的完成工程作为新作品。
6. 首次生成与缓存命中分别记录。
7. 修改第二句后第一句保持不变。
8. 重新打开工程时能正确恢复，缓存文件缺失时有明确处理。

测试输入可以固定用于自动回归，但正式生成结果必须由实际运行的模型与引擎产生。

### T4. 听感验收

输出至少两组完整作品，以及同一乐句的不同调教版本。

进行人工试听记录：

- 旋律是否仍像音阶练习。
- 歌词节奏是否自然。
- 是否有明显错音或突兀跳进。
- 绮萱是否有机械咬字。
- 句尾是否自然。
- 人声是否被伴奏淹没。
- 副歌是否具有情绪推进。

区分音乐逻辑错误、合成发音错误和主观风格差异。

## 七、交付标准

用户不需要了解工程结构。

只需打开 SONGYU，输入自己的想法或歌词，点击创作，得到一首真正由本次输入生成的短歌。

用户可以继续编辑一两个音符、调节绮萱的演唱，再导出最终作品。

**最终目标不是证明模型能发声，而是证明 SONGYU 能自由创作、可编辑、可重生成，并完成真实作品交付。**

开发完成后，分别提交红茶和小由的功能分支，创建 PR。由项目成员完成合并与最终真实验收。
