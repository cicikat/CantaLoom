# 工单 40｜CantaLoom 一键成歌 V1.1：低能力模型兼容、失败自愈与成品交付

> **交付对象：Codex（后端优先，前端只做必要接线）**
> **仓库：** https://github.com/cicikat/CantaLoom
> **核查基线：** `main @ cec720a0a977679ad3fbde1267a7bee4d708e600`（2026-11-14 查阅）
> **目标：** 用户只输入灵感（可选提供歌词、BPM、目标时长），系统自动完成 **规划 → 旋律 → 编曲 → 演唱 → 混音 → 音频验收 → WAV 成品**；即便 DeepSeek / Gemini 等模型输出不规范，也能在预算内定向修复、切换预配置的备用模型，或者以可恢复的明确错误停下。
> **范围限制：** 暂不做可中途编辑的 Agent 工作台，不改视觉设计、不引入复杂新音乐编辑能力；保留现有逐句编辑、锁定、调教、Canvas / HTML PV 的独立功能及兼容性。HTML PV 不作为本轮音频成功的强依赖。

## A. 当前仓库的已验证事实（阅读代码所得，非运行测试）

- `server/services/llm-router.mjs` 已有 Zod / JSON Schema 提示、`response_format: {type:'json_object'}`、任务路由、默认 2 次 / 旋律 3 次尝试。**但对所有服务商固定同一请求格式**；第二轮仅附通用提醒，没有返回具体 Zod 或音乐校验错误；请求连接异常直接失败；没有空字符串、`finish_reason='length'` 的独立分类，也没有 `max_tokens` 配置。
- `server/services/free-composition.mjs` 通过 `lyrics_planning` 生成 `freePlanSchema`，再用 `melody_composition` 生成 `melodyDraftSchema`。后者过于复杂，包含输入已有的歌词/乐句 ID/时间、音符 ID 和丰富的表演字段，对小模型非常不友好。
- `shared/melody.mjs` 已实施歌词逐字对齐、锁定、调式/和弦、非均匀节奏等严谨校验。**这些不应因为模型弱而降低。**
- `server/services/production.mjs` 自动运行 composing / instruments / singing，成功停留在 `ready-for-mix`；内存 `Map` 管理任务。失败时只保留笼统阶段提示；对外仅提供特定 singing 乐句重试，规划/旋律/器乐失败缺恢复入口；重启任务状态丢失。
- `src/hooks/useProduction.ts` 只轮询；重试仅限演唱句；`src/components/FreeCreation.tsx` 提供灵感、可选歌词/BPM/20–30 秒、进度展示，未整合完整 WAV 成品自动交付。
- `src/hooks/useStudio.ts`、相关编辑组件里已有人工修改歌词、音符/调教功能。本轮应**暂不将其改造成中途审批流程**。
- `server/services/performance-planner.mjs` 的演唱表现规划属于可配置的扩展任务：如果配置后失败会阻断演唱（而非自动跳过），需明确设计质量/完成策略，不允许悄悄绕过。

## B. 设计原则（不可违反）

1. **永不伪造成功。** `mock`、`local-rules`、真实 LLM、备用模型、自动修复来源严格标注；不能把本地模板假扮成 AI 旋律，不能把没有实际合成的声音称为完成。
2. **内容不篡改。** 用户手写歌词、BPM、目标时长范围、已有锁定字段必须原样保留；程序不能为了通过校验偷偷改字、删句、重排音符身份或填充用户未授权的歌词。
3. **降低生成任务难度，而非放宽最终验收。** 模型输出更小的草稿，服务端负责确定性组装，并对最终规范工程执行原有强校验。
4. **可预见的有界成本。** 每阶段最多限定尝试次数、累计超时/Token/请求预算；只有预先配置并可用的备用模型才允许自动切换。任何未知计费不得当作 0 费用。
5. **重启/网络异常后能续做。** 同一作业不会因为前端刷新重复调用昂贵模型或重算已经验收、指纹一致的 WAV。不要依靠浏览器常驻。
6. **真机资源不足必须报错。** 音源/声库/FluidSynth/FFmpeg 不能用静音、假 WAV 或固定 Mock 代替。

## C. P0-1｜LLM 兼容适配层与精确错误分类

**涉及：** `server/services/llm-router.mjs`、`server/admin-config.mjs`、`server/public/admin.js`、`shared/contracts/*`、测试。

- 保留现有 `lyrics_planning / melody_composition / performance_planning / pv_design` 路由和已有密钥引用；配置向后兼容。
- 为单个连接新增明确的 `structuredOutputMode` 能力配置：例如 `json_schema` / `json_object` / `text_json`（名称按实现定，默认延续既有 `json_object`），以及可选 `maxOutputTokens`、请求超时、兼容参数。只向**确认支持**的端点发送 Schema；不要盲目发送所有模型不支持的字段。Gemini 可使用官方支持的结构化模式；DeepSeek Chat Completions 的 JSON Object 模式按文档处理空内容。禁止对 401/403/余额问题尝试格式降级。
- 将错误分为机器可读 `code`：`UPSTREAM_AUTH`、`UPSTREAM_RATE_LIMIT`、`UPSTREAM_UNAVAILABLE`、`UPSTREAM_TIMEOUT`、`FORMAT_UNSUPPORTED`、`EMPTY_CONTENT`、`OUTPUT_TRUNCATED`、`JSON_PARSE_FAILED`、`SCHEMA_VALIDATION_FAILED`、`SEMANTIC_VALIDATION_FAILED`、`BUDGET_EXCEEDED`、`DEPENDENCY_UNAVAILABLE`。必要时追加，不暴露密钥、原始响应全文和敏感日志。
- 检查 `choices`、`message.content`、`finish_reason`、上游 HTTP 状态、Token 统计；空格内容不是合法成功；`length` 截断不能仅交给 JSON.parse；显示用户可理解中文解释。
- **轻量语法修复器**仅允许无损操作：清 BOM、外围 Markdown 代码块、首尾空白、可识别的单个 JSON 对象包装。对缺字段、非法音高、对不上歌词等**语义问题绝不猜补**。
- 按 Zod issues 汇总简短、脱敏的字段路径/期望类型/约束（例如 `phrases[2].notes[4].duration`），并将具体失败原因发给后续纠错请求；若是音乐校验异常，转换为可分类、可定位的校验诊断。保留最近一次失败输出只在本次安全内存重试上下文内，长度截断，绝不写带隐私的日志。
- 重试策略建议 **每阶段总计最多 3 次生成调用**：首次生成 → 同模型带错误说明定向纠错 → 已配置备用模型（若无备用则明确失败）。网络异常适用退避 + jitter / `Retry-After`，在共享预算内执行；不可无限循环，也不得对认证失败盲重试。
- 对格式不支持，仅在精确识别后做**一次**受控能力降级 / 明确提示配置错误，不能把任意 HTTP 400 当作结构化输出问题。
- 追溯：每阶段记录所选模型、路由、结构模式、尝试次数、错误类别、Token、耗时、是否启用自动修复/备用；费用仅根据已配置费率估算，不记录 API Key/完整原始提示与原始响应。

**验收：** 空格响应、截断、非法 JSON、合法 JSON 但 Schema 错、合法 Schema 但音乐规则错、429/503、超时、400 不支持格式、401/403、重试成功/穷尽，都有确定的路由决策与稳定错误码；无失控调用。

## D. P0-2｜缩小模型输出契约，让弱模型只作音乐决策

**涉及：** `server/services/free-composition.mjs`、`server/services/melody.mjs`、`shared/contracts/free-composition.mjs`、`shared/contracts/melody.mjs`、`shared/free-timeline.mjs`、`shared/melody.mjs`。

- 保留现有对外 `freeResultSchema`、`melodyDraftSchema`、`SongProject`，新增**内部专用、版本化、最小草稿契约**，不要让前端和旧工程受破坏。
- `lyrics_planning` 只生成用户未提供的创造性字段（主题、情绪、原创歌词、和声/能量、相对句长等）；用户已给歌词/BPM 不再要求模型回显并重新生成这些字段；后端合并用户原值，核对音节长度/section 与结构。
- `melody_composition` 内部优先让模型按输入 `phraseId` 输出简短音符意图（相对起点/时长/音高或音级/歌词索引等），**不要求重复返回**用户歌词、绝对时间轴、note ID、锁定状态、performance 大对象。定义统一的轻量字段及示例；服务端注入 UUID/ID、已知歌词、起止、力度默认值、锁定字段，按绝对 beat 重建原契约。
- 音乐规则（每字对应、连音 `+`、不重叠、调内、和弦强拍、时值差异、动机引用）继续用现有 `validateMelody` 最终验收。对模型错误允许指定乐句或指定片段的**局部重新生成**；若缺少局部接口，先完成整段有界重试，后续单独优化。
- 若模型不能可靠处理中文逐字音符分配，可进一步输出短的节奏/音高轮廓草案，由**确定性的对齐器**根据原歌词构造音符；必须验证停顿、音节数量、音符时长、边界，不能用机械等分默默交付。
- 不得回退到连续音阶或无变化的重复模板并宣称高质量。原有 `localMelody` 仅作为**显式允许且标记为规则生成**的可选完成优先模式，默认真实 LLM 失败后继续保留失败状态，直到换模型成功或用户自行选择。

**验收：** 旧 API / 项目照常读取；真实生成草稿的复杂度显著下降；对用户手写歌词逐字符一致；内部小契约由有问题的 Fake 模型也能在重试范围内转成合法工程；最后一道音乐校验不放松。

## E. P0-3｜阶段级断点与可恢复生产任务

**涉及：** `server/services/production.mjs`、`server/routes/production.mjs`、`shared/contracts/production.mjs`、`src/api/client.ts`、`src/hooks/useProduction.ts`。

- 将任务明确拆分为：`preflight → lyrics_planning → melody → score_build → performance_planning (if configured) → instruments → singing → mixing → qa → completed`。对外可保留旧枚举的兼容映射或显式契约版本；前端不能猜测未支持状态。
- 存储最小的**可恢复检查点**（建议放仓库外的 `externalRoot/runtime/jobs/`，原子文件写/重命名，带 schemaVersion），保存任务输入指纹、已校验计划/旋律/工程快照、各阶段完成标记、资产指纹、失败码、更新时间、可续传状态。不得落盘密钥或冗余原始模型响应；旧工程序列化继续支持。
- 为每个阶段设计幂等规则：通过输入指纹比较决定是否复用，断点重试绝不覆盖后续用户修改的数据；允许因参数/模型变化使其下游失效。资源有版本和 hash，旧产物不会被误当成新作品。
- 启动重启后识别 `running` 任务为 `interrupted`，可以恢复（若能安全自动恢复则允许），原 `jobId` 可查询；不再简单 404 丢失。支持阶段级 `POST /api/production/:id/resume`（建议），并保留已有单句 retry 向后兼容。
- `instrument` 或某句 `singing` 失败后只重算该阶段/失败句，校验成功的资产可以复用；`planning` / `melody` 失败保留已经成功的前置结果，不要求用户从头重新输入。
- 全局限流：同一任务不能被两个继续请求同时启动；保留请求代次、取消后不回写被替换的工程，限制任务历史与文件清理策略；区分「停止等待」和「后端任务已取消」。
- 所有失败必须能回答：**哪一阶段、什么类别、已经完成了什么、会不会收费重试、能否续做**。不要向 UI 泄露内部堆栈。

**验收：** 规划后重启、旋律后重启、器乐渲染中断、某句演唱失败、前端刷新/换页/取消/迟到请求，各自恢复正确；同一个已成功产物没有重复生成、没有失败被误标成功。

## F. P1｜自动输出真正可下载的完整成品

- 当前 `ready-for-mix` 不是完整的一键交付。复用现有 `renderAudio` / `FFmpeg` / 音频混音链路，在最后一句演唱验收后自动进行一次总混（器乐+人声+已有混响/增益设置），产出**真实立体声 WAV**，形成稳定 artifact 地址并绑定生成记录。
- 自动质量门禁：文件可读取、有效 PCM、非空/非全静音、时长与期望范围一致、无 NaN 或无效采样、音轨确实存在且来源真实；响度/true peak 使用现有量测能力，严重削波作为失败或明确告警。具体响度目标经既有测试样本校准，**不要生搬硬套固定 LUFS 数值**造成误杀。
- 如果合成成功但主混失败，回退到 `mixing` 阶段恢复，不能重新请求歌词和旋律。
- 前端完成态应有：试听、下载 WAV、简要歌词/曲名/时长、来源/模型简要信息，以及「重新制作」；失败态显示失败阶段、可重试入口、是否保留已有产物，不能展示假百分比。
- AI HTML PV / MP4 仍保持**独立可选的后续动作**：没有 Chromium 或 `pv_design` 时，音频制作不能因此失败；可在 V1.2 再加入「音频完成后自动制作带歌词 PV」开关。

## G. P1｜自动音乐质量最低门槛（不求造一个主观审美评分 AI）

- 检查歌词逐字完整、句子/音符数量一致、有效音高与长短句分配、切换段落的和声一致性、休止与乐句收尾、至少出现非模板的时值差异；用已实现的音乐校验做硬门槛，新增可解释的轻量质量诊断即可。
- 采集可追溯诊断：词曲错误次数、各阶段成功率、备用模型切换、每次成功成本/耗时、成品检测结果。**质检通过只代表没有检测到硬错误，不代表艺术质量已达专业水准。**
- 不能以「追求通过率」为由降低锁定、中文发音、音节对齐、真实演唱、音色来源等条件。
