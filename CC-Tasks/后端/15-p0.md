## 总体要求

从当前自动生成短歌的系统，升级为支持人工精细调声、局部重唱、长歌曲编曲、模型路由及专业混音的音乐制作引擎。

执行前阅读 `AGENTS.md`、`docs/ARCHITECTURE.md`、`docs/TEAM_WORKFLOW.md`，检查最新 main 和现有工单。

**开发原则：**

- 只修改后端、音乐核心、共享契约和必要的跨层音频适配代码。
- 不直接修改 Toge 负责的 React 页面、UI、Mock。
- 优先扩展已有接口，避免建立重复 API。
- 所有新接口提供 Zod Schema、TS 类型、请求/响应示例与错误语义。
- 不使用硬编码歌词、固定音符或伪造 WAV 替代真实生成。
- 分阶段开发，每阶段独立测试、提交与验收，未经确认不连续实施后续阶段。
- 不在本工单中进行无关架构重构。

## P0 · 精细调声与单句重唱

现有基础：`src/melody.ts`、`shared/performance.mjs`、`server/services/qixuan.mjs`、`src/audio.ts`。

- [x] 检查音符、歌词、演唱表现、音频资产的依赖关系。结论：演唱依赖＝本句歌词/音符/BPM/起止/Performance（resolvePerformance）/声库与引擎版本/runner，逐句独立；器乐按轨道独立缓存；服务端缓存键另含 take 与渲染修订。设计已满足逐句精准失效，本轮补齐 Pitch 曲线自动纳入依赖。
- [x] 完善音符的音高、起点、长度、锁定与歌词对齐校验。`editPhraseNotes`（src/melody.ts）：等数量、同 ID、同顺序、同音节，逐音符 melodyNoteSchema 校验 + 越界/重叠检查，锁定音符逐字段保护。
- [x] 设计可保存、可编辑的 Pitch 曲线数据结构，并接入 OpenUtau USTX 渲染。`performanceSchema.overrides[].pitch`（x=毫秒、y=十分之一半音、shape=io/i/o/l，2–64 个严格递增点），经 `notePerformance` 替换该音符自动过渡点（snap_first=false）；契约见 shared/contracts/CHANGELOG.md v0.3.3。
- [x] 支持修改单句歌词后，选择保留原旋律或重新作曲。`setLyricText(project,id,text,{keepMelody})`：保留旋律要求唱字数一致并重挂音节；否则清空音符与旧索引 overrides，走 melodyRequest + targetIds 重新作曲。锁定边界（2026-11-07 修复）：会改写锁定音符唱字的保留旋律操作、句内含锁定音符的重新作曲均明确拒绝，不静默覆盖，失败不修改工程。
- [x] 支持单句重新演唱，其他句子及伴奏不重复生成。复用 `POST /api/singing/qixuan/render`（take 递增），未新增端点；真实验收确认第一句资产与 FluidSynth 器乐缓存键不变。
- [x] 实现修改后音频缓存精准失效、版本保存及失败回滚。vocalHistory 保留 3 版；新增 `restoreVocalAsset`（仅依赖与 runner 匹配可恢复，过期明确拒绝）；服务端渲染改 pending 文件 + 校验后原子改名，失败不留半成品、旧 take 保留。
- [x] 处理单句 WAV 的起止位置、padding、衔接、淡入淡出及混响尾音。startSeconds 落位不变；新增 `phraseEdgeFades`（padding 内 50 ms 淡入/150 ms 淡出，主体不触碰），干声与处理分轨一致生效。
- [x] 确保修改后的演唱可重新融入全曲混音，无明显时间偏移或爆音。真实验收：全曲时长不变、第一句区域逐样本一致、干声零削波样本、混音峰值受控、接缝 edgeIn 0.049 / edgeOut 0。
- [x] 添加真实引擎回归测试，验证新旧 WAV 差异与其他资产缓存稳定性。`tests/qixuan-real.test.mjs`（真实推理、缓存命中/失效、PCM 差异、无 pending 残留；无引擎自动跳过，`SONGYU_REAL_TESTS=0` 关闭）。

**验收：** 修改第二句歌词、音高和 Pitch，重新演唱后正确融入原曲，第一、三句与器乐资产保持不变，旧版本可恢复。——已通过：`tests/browser/p0-resing.spec.ts` 真实引擎验收（2026-11-07，本机 CPU runner，1.1 分钟），产物在外部根目录 `runtime/exports/p0-resing/`（p0-resung-mix.wav、p0-acceptance.json）；数字见 [迭代日志](../../docs/iteration-log.md)。

### P0 交接 Toge（接口、Schema、示例与语义）

本轮**无新 HTTP 端点**；单句重唱/改词/调音复用现有接口与共享函数，跨层触碰 `src/audio.ts`、`src/audio-mix.ts`、`src/features/singing/qixuan.ts`（工单范围），PR 需 toge review。

| 能力 | 入口 |
|---|---|
| 改词（保留旋律/重新作曲） | `setLyricText(project,lineId,text,{keepMelody})`（src/melody.ts）；重新作曲后接 `melodyRequest` → `api.melody` → `applyMelodyDraft`（targetIds=[lineId]） |
| 编辑音高/起点/长度 | `editPhraseNotes(project,lineId,notes)`（src/melody.ts），整数组提交、原子应用 |
| Pitch 曲线调教 | `setPhrasePerformance(project,lineId,{mode:'manual',overrides:[{index,origin:'manual',pitch:[...]}]})`；Schema：`pitchPointSchema`/`pitchCurveSchema`（shared/contracts/melody.mjs + .d.mts 的 `PitchPoint`） |
| 单句重唱 | 沿用 `generateLine`/`applyVocalResult`；渲染请求与响应契约不变 |
| 恢复历史演唱 | `restoreVocalAsset(project,lineId,index)`（src/features/singing/qixuan.ts） |

1. 请求/响应示例：Pitch 覆盖片段 `{index:0,origin:'manual',pitch:[{x:-80,y:-60,shape:'io'},{x:30,y:0,shape:'io'},{x:200,y:40,shape:'l'}]}`；`POST /api/singing/qixuan/render` 请求体在既有 `performance` 字段内携带，响应契约不变（新 take 新 audioUrl）。
2. 字段含义：x=相对音符起点的毫秒（负值为先入）、y=十分之一半音整数（±1200）、shape 为 USTX 插值；2–64 个按 x 严格递增的点。提供时替换该音符自动过渡点；删除 pitch 字段即恢复自动。
3. 状态说明：歌词/音符/锁定在生成期间变化 → applyVocalResult 抛错且工程保留；渲染失败 → 旧资产保留；restoreVocalAsset 在依赖或 runner 不匹配时抛「不能恢复」；editPhraseNotes/setLyricText 全部先校验后替换，失败工程不变。
4. 缓存失效：仅本句歌词/音符/Performance（含 pitch）变化使本句演唱依赖失效；兄弟句与器乐缓存不变；重新作曲（notes 清空）同时清除该句按旧索引的 overrides。
5. Mock 与测试证据：Mock 当前不返回 pitch（扩展归 toge，夹具须显式 mock 标记）；真实证据见 tests/p0-tuning.test.ts、tests/qixuan-real.test.mjs、tests/browser/p0-resing.spec.ts 与迭代日志 2026-11-07 条目。

每次接口交付必须附带：

1. 请求与响应 JSON 示例。
2. Schema / TypeScript 类型及字段含义。
3. 正常、失败、取消、过期等状态说明。
4. 缓存失效规则及局部重生成语义。
5. Mock 数据规范和真实测试证据。

**注意：** 单句正常修改后的重唱，不等同于已有 production 失败重试接口。优先复用 `/api/singing/qixuan/render`，只有真实业务需求无法覆盖时才增加端点。
