# 工单 22：制作后端治理（缓存、任务持久化、渲染并发）

Owner：Blacktea / Backend & Music Engine。状态：待排期。
来源：2026-11-07 专业音乐人视角后端评审（锐评 P2 项）+[工单 12](../12-admin-backlog.md) 第 1/3 项的实施细化。本单领取 12 的这两项，checkbox 以本单为准；12 保留总清单，不回写复制。
范围：server/ 内部治理。不改公共创作 API 语义；管理页展示字段如需新增走 ENGINES.md 边界（不返回密钥/敏感路径以外信息）。

## 应做清单

- [ ] 音频缓存治理（领取 12 第 3 项）：`runtime/cache` LRU 淘汰 + 总容量上限（容量默认值实施时定并写入 ENGINES.md）；淘汰不得删除 pending 文件与被内存任务引用的资产；管理页/诊断 API 展示缓存占用与淘汰计数。
- [ ] 制作任务持久化（领取 12 第 1 项）：production 任务状态落盘（SQLite 或 append-only JSON，选型理由写入工单），重启后 `GET /api/production/:id` 可查询历史状态；运行中任务的恢复策略明确为「标记中断可重试」还是「断点续跑」，不假装无缝恢复。
- [ ] 渲染并发隔离：FluidSynth 乐器渲染改为有界并发池（区别于歌声的全局串行队列），统一超时与并发上限；`runProcess` 默认超时的调用点差异（120s/600s）收拢为显式参数表。
- [ ] （可选）LLM 任务并发/速率上限：防止制作任务风暴打满上游配额，超限明确排队或拒绝，不静默丢弃。
- [ ] 测试：缓存淘汰保护 pending/引用中资产；重启后任务可查询、中断任务语义符合声明；并发池压测（多轨并行渲染耗时下降且结果字节一致）；既有缓存命中回归不破。

## 验收

缓存在超限后按 LRU 收敛且进行中的渲染零损坏；服务重启后历史任务状态可查、中断语义与工单声明一致；多轨制作总耗时较串行基线可测下降，分轨产物字节与串行一致。完成记录写入 [迭代日志](../../docs/iteration-log.md)，注明本工单与工单 12。
