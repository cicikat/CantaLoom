## 核心目标

解决当前两个问题：

A. 歌词旋律由固定音阶走势、等间距音符生成，音乐机械。

B. 绮萱虽已真实推理，但演唱缺乏自然的音符时值、音高过渡与表现力。

最终让用户输入全新原创歌词和创作意图，生成真正不同的旋律，并通过绮萱演唱。

## P0｜先定位问题

检查 `guidedLyricNotes()`、`lyricNotes()`、SongPlan、OpenUtau USTX、`server/qixuan.mjs` 和桥接器。

准备两组对照：

- 当前自动生成的音符。
- 一段手工编写、包含重复音、跳进、长音和休止的旋律。

使用同一个绮萱声库与推理参数合成。

比较实际音高、时值与声音表现，判断机械感有多少来自作曲、有多少来自歌声调教。

记录结果，不先用随机音高扰动掩盖问题。

## P1｜真正的动态旋律创作

扩展现有 LLM 创作链路。

现有 SongPlan 负责宏观音乐规划，需要增加独立的 MelodyDraft / PhrasePlan 层，负责真实乐句。

建议结构包括：

- 句子 ID
- 用户歌词
- 乐句起止时间
- 音符音高
- 音符起点与时值
- 歌词和音符对齐
- 休止与延音
- 乐句动机与重复关系
- 旋律生成来源

允许 LLM 输出经过约束的结构化乐句，由本地验证器转换为 MIDI Note。

必须支持：
- 重复音，而不只是连续上行或下行。
- 长短不同的音符。
- 歌词中的停顿。
- 一个字跨越多个音符。
- 动机重复与变化。
- 根据和弦进行检查音高兼容性。
- 根据句子长度安排乐句。

用户手写的歌词不能被重新作曲自动覆盖。

不要用简单随机数替代作曲，也不要继续通过等分歌词长度生成全部演唱音符。

## P2｜自由创作模式

支持以下输入路径：

1. 用户只提供创作主题，LLM 生成原创歌词和旋律。
2. 用户提供自己写的歌词，Agent 保留歌词并生成对应旋律。
3. 用户已编辑部分音符，Agent 只补全没有锁定的部分。

不要让用户只能从三种预设风格、四句固定歌词中选择。

先在约 20–30 秒的短歌范围内打通自由输入；扩展歌曲时长可以之后实施。

提供局部操作：

- 重新生成指定一句旋律。
- 保留歌词，只重生成旋律。
- 保留旋律，只调整演唱表现。
- 锁定部分音符或整个乐句。

每次操作必须保留无关段落与音轨。

## P3｜绮萱演唱调教

在现有 OpenUtau / DiffSinger 桥接基础上实现可验证的演唱参数。

优先处理：

1. 音符时值、休止与自然连音。
2. 音高过渡与 Pitch Bend。
3. 合适长音上的 Vibrato。
4. DYN 音量与乐句强弱。
5. 中文发音时机与辅音对齐。

再检查绮萱声库是否支持 BREC、VELC、ENE、PEXP 等表达参数。仅对实际支持的参数实现控制。

将调教数据保存在工程中，并映射到 USTX。

先提供三种演唱表现预设：

- 自然
- 轻柔
- 强烈

它们必须产生实际演唱参数与音频差异，而不只是 UI 标签。

保证同一句旋律可以单独重新调教，不要求整首重新生成。

## P5｜真实动态验收

使用当前已配置的 LLM API。

至少测试三种没有预先写进源码的输入：

A. 用户自行提供一段忧伤的原创中文歌词。

B. 用户仅提供一段热烈的夏日主题，由 LLM 创作歌词与旋律。

C. 用户提供已锁定的部分音符，请 Agent 续写剩余旋律。

每组都验证：
- 有真实 LLM 请求记录。
- 歌词不是固定模板替换。
- 音符具有非均匀时值。
- 旋律有实际重复、变化或停顿。
- 与现有和声基本兼容。
- 绮萱真正生成中文演唱。
- 真实音频可试听、混音和导出。
- 修改一句不会重新生成其他句。

保留本地规则模式，但不能把本地测试夹具结果当作 LLM 实际效果。
